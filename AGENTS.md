# AGENTS.md

PPT Master packages presentation workflows, SVG/PPTX tools, and reusable design references. Source documents become editable PowerPoint decks through source intake, a shared design spec, page generation, validation, and export.

## Task routing

For presentation generation or revision, read [skills/ppt-master/SKILL.md](skills/ppt-master/SKILL.md). It owns the deliverable, source-preservation rules, and route pointers. For repository maintenance, read only instructions and references governing the files being changed; maintaining a script or document does not start a presentation workflow.

[routing.md](skills/ppt-master/workflows/routing.md) distinguishes native template filling, strict 1:1 beautification, new SVG-based decks, reusable templates, and native enhancement. Preserve these artifact contracts. Creating a needed intermediate artifact within an authorized request does not require a new user message before continuing.

## Editing and verification

Preserve the working tree and existing public script contracts. Follow relevant conventions under [docs/rules/](docs/rules/) while matching the edited directory's language. For agent instructions, favor concise purpose, essential constraints, precise reference triggers, and observable completion; use a fixed format or sequence only where it serves an actual contract.

Documentation-only changes need diff, reference, schema, and consistency checks. Script changes need the affected command and behavior checked. Generated decks additionally need the relevant SVG, asset, chart, and export checks defined by their route. A workflow label or a successful subprocess does not itself prove the final deck is correct.

Repository maintenance does not require a worktree, new tests, branch, presentation project, or role-switch ceremony. Commit, push, installation, publication, credential changes, and relocation of original user material follow the task's existing authorization.
